# 봉안당 분양/예약/재판매 플랫폼 — 전체 시스템 아키텍처

## 1. 개요

한국 전용 봉안당 분양 플랫폼으로, **멀티 사업자**가 입점하고 **모바일 앱 우선**으로 일반 사용자·영업·업체·슈퍼관리자 역할을 지원한다.

- **클라이언트**: 모바일 앱(React Native), 관리자 웹(Next.js)
- **서버**: 단일 백엔드 API(NestJS)
- **데이터**: PostgreSQL, S3 호환 스토리지
- **외부 연동**: 네이버 지도, 네이버/카카오 로그인, 휴대폰 인증, FCM 푸시, (추후) PG·SMS

## 3. 역할별 진입점

| 역할 | 클라이언트 | 주요 기능 |
|------|------------|-----------|
| **USER** | 모바일 앱 | 시설 검색·상세, 좌석 선택, 대기열 참여, 계약, 재판매 신청, 마이페이지 |
| **SALES_MANAGER** | 모바일 앱 | 추천 링크/코드, 내 추천 고객, 계약 진행, 수수료 조회 |
| **OPERATOR_ADMIN** | 관리자 웹 | 시설/층/구역/칸, 가격, 계약·재판매 승인, 대기열 현황 |
| **SUPER_ADMIN** | 관리자 웹 | 사업자 관리, 전체 시설/계약/회원, 시스템 설정 |

## 4. 핵심 설계 원칙

### 4.1 멀티 사업자
- 모든 시설·칸·계약·대기열·재판매는 `operator_id`로 사업자 소속 구분.
- API·DB 조회 시 역할에 따라 operator 범위 필터 적용.

### 4.2 계약 이력 불변
- 계약 레코드는 수정·덮어쓰기 없음.
- 재판매 시: 기존 계약 `TRANSFERRED` + 신규 계약 생성.

### 4.3 대기열 정책
- 선점형 아님. 순번 도달 시 24시간 구매 기회(ACTIVE).
- ACTIVE 1건만 허용. 만료 시 다음 순번 자동 승격.
- 알림: 7일 전, 1일 전, ACTIVE 진입 즉시.

### 4.4 결제·인증 확장성
- 결제: PG 미연동 시 mock 상태로 흐름 검증, Payment Service 추상화로 추후 PG 어댑터 교체.
- 인증: `users` + `auth_identities`(소셜/일반 병합 가능), 휴대폰 인증·소셜 로그인 어댑터 구조.

### 4.5 한국/모바일 우선
- 지도: 네이버 지도 기준 설계.
- 주소: 도로명/지번/상세 구분, 좌표 저장.
- UX: 모바일 앱 기준, 관리자만 PC 대응.

## 6. 보안·인가

- **인증**: JWT(액세스/리프레시), 소셜 OAuth, 휴대폰 인증.
- **인가**: Role Guard — `SUPER_ADMIN` | `OPERATOR_ADMIN` | `SALES_MANAGER` | `USER`.
- **데이터 범위**: OPERATOR_ADMIN/SALES_MANAGER는 소속 operator만 접근.
- **민감 정보**: 비밀번호 해시, 휴대폰/이메일 암호화 저장 정책 적용 권장.
